# Docker для аналитиков

## Образы и контейнеры

Образ описывает окружение: систему, библиотеки и код. Контейнер это запущенный экземпляр образа. Образ собирается по файлу Dockerfile командой docker build -t имя:тег .

## Dockerfile

Слои кэшируются, поэтому порядок инструкций важен. Сначала копируют файл зависимостей и устанавливают их, и только потом копируют исходный код. Тогда изменение кода не заставляет переустанавливать все пакеты.

Базовый образ лучше брать облегчённый, например python:3.11-slim. Секреты, пароли и токены в образ не записывают: их передают через переменные окружения при запуске.

## Данные и тома

Всё, что записано внутри контейнера, пропадает при его удалении. Данные, которые должны сохраниться, кладут в том (volume) или монтируют папку хоста флагом -v.

## Docker Compose

Если приложению нужно несколько сервисов, например база данных и веб-приложение, их описывают в файле compose.yaml и поднимают одной командой docker compose up -d. Сервисы внутри одной сети обращаются друг к другу по имени сервиса.

## Ресурсы

Ограничить память контейнера можно флагом --memory, процессор флагом --cpus. Для работы с видеокартой NVIDIA нужен NVIDIA Container Toolkit и флаг --gpus all.
