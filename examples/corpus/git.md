# Работа с Git в команде

## Ветки

Основная ветка репозитория называется main. Напрямую в неё никто не пушит: любое изменение идёт через отдельную ветку и pull request. Ветку называют по шаблону тип/краткое-описание, например feature/user-segments или fix/null-dates.

Перед началом работы ветку создают от свежей main командой git switch -c feature/имя после git pull.

## Коммиты

Сообщение коммита пишется в повелительном наклонении и отвечает на вопрос «что сделает этот коммит»: «Добавить фильтр по региону», «Исправить расчёт retention». Первая строка не длиннее 72 символов.

Один коммит содержит одно логическое изменение. Если в процессе работы накопилась мешанина, перед отправкой её приводят в порядок через git rebase -i.

## Pull request и ревью

В описании pull request указывают, что изменено и как это проверить. Ревью обязательно минимум от одного коллеги. После одобрения ветку вливают способом squash and merge, чтобы история main оставалась линейной.

## Отмена изменений

Чтобы отменить уже опубликованный коммит, используют git revert: он создаёт новый коммит с обратными изменениями и не переписывает общую историю. Команду git reset --hard применяют только к локальным изменениям, которые ещё никто не видел.

Случайно удалённую ветку обычно можно восстановить через git reflog, где хранится история перемещений HEAD.
